## Directory Purposes

**`src/daemon/`:**
- Purpose: All daemon-side code — runs in the long-lived background process
- Contains: `AgentManager` (agent lifecycle), `AgentProcess` (per-agent supervisor), `IPCServer`/`IPCClient` (socket IPC), `FastChecker` (inbox polling), `WorkerProcess` (ephemeral workers)
- Key files: `agent-manager.ts`, `agent-process.ts`, `ipc-server.ts`, `fast-checker.ts`, `worker-process.ts`, `index.ts`

**`src/bus/`:**
- Purpose: Filesystem-based agent bus operations
- Contains: One file per domain — `message.ts`, `task.ts`, `event.ts`, `heartbeat.ts`, `approval.ts`, `system.ts`, `experiment.ts`, `catalog.ts`, `metrics.ts`, `reminders.ts`, `knowledge-base.ts`, `oauth.ts`
- Key files: `message.ts` (inbox send/check/ack), `index.ts` (re-exports all bus functions)

**`src/cli/`:**
- Purpose: All CLI subcommand implementations
- Contains: One file per command
- Key files: `index.ts` (registers all commands), `bus.ts` (all `cortextos bus *` subcommands ~1300 lines), `start.ts`, `add-agent.ts`, `enable-agent.ts`

**`src/pty/`:**
- Purpose: PTY abstraction over `node-pty`
- Contains: `agent-pty.ts` (spawns `claude` with env vars and args), `output-buffer.ts` (ring buffer + bootstrap detection), `inject.ts` (PTY stdin injection with dedup)
- Key files: `agent-pty.ts`

**`src/hooks/`:**
- Purpose: Claude Code hook scripts invoked at agent lifecycle events
- Contains: One hook per event type
- Key files: `hook-crash-alert.ts` (SessionEnd), `hook-ask-telegram.ts` (PermissionRequest), `hook-permission-telegram.ts`, `hook-planmode-telegram.ts`

**`src/types/`:**
- Purpose: Shared TypeScript types for the entire codebase
- Key files: `index.ts` — defines `AgentConfig`, `BusPaths`, `CtxEnv`, `InboxMessage`, `Task`, `Event`, `Heartbeat`, `Approval`, `IPCRequest/Response`, `WorkerStatus`

**`src/utils/`:**
- Purpose: Low-level primitives used throughout
- Key files: `atomic.ts` (atomic file writes), `paths.ts` (canonical path resolution), `env.ts` (env var resolution), `lock.ts` (file locks), `validate.ts` (sanitization)

**`templates/`:**
- Purpose: Starter agent directories copied by `cortextos add-agent` and dashboard agent creation
- Contains markdown files (AGENTS.md, SOUL.md, IDENTITY.md, HEARTBEAT.md, etc.), `config.json`, `goals.json`, `.claude/settings.json` (hook config)
- Key files: `templates/agent/`, `templates/orchestrator/`, `templates/analyst/`

**`dashboard/src/lib/`:**
- Purpose: Server-side logic for the Next.js dashboard
- Key files: `db.ts` (SQLite singleton), `sync.ts` (file→SQLite sync), `watcher.ts` (chokidar + SSE), `auth.ts` (NextAuth), `config.ts` (path helpers), `ipc-client.ts` (daemon control)

**`dashboard/src/app/api/`:**
- Purpose: Next.js API routes
- Key routes: `GET/POST /api/agents`, `GET /api/agents/[name]`, `POST /api/agents/[name]/lifecycle`, `GET /api/events/stream` (SSE), `GET /api/messages/stream/[agent]` (SSE), `POST /api/messages/send`

**`community/skills/`:**
- Purpose: Installable skill packages (installed via `cortextos install`)
- Each skill is a directory containing markdown files and shell scripts that extend agent capabilities

## Key File Locations

**Entry Points:**
- `src/daemon/index.ts`: Daemon process entry point → `dist/daemon.js`
- `src/cli/index.ts`: CLI entry point → `dist/cli.js` (bin: `cortextos`)
- `dashboard/src/app/(dashboard)/page.tsx`: Dashboard home page
- `dashboard/src/middleware.ts`: Auth + CORS middleware for all routes

**Configuration:**
- `tsconfig.json`: TypeScript config
- `package.json`: Root package scripts (`build`, `test`, `typecheck`)
- `ecosystem.config.js`: PM2 daemon config
- `dashboard-ecosystem.config.js`: PM2 daemon + dashboard config
- `dashboard/.env.example`: Dashboard env var reference

**Core Logic:**
- `src/daemon/agent-manager.ts`: Multi-org agent discovery and lifecycle management
- `src/daemon/agent-process.ts`: Per-agent crash recovery, session timers, PTY coordination
- `src/daemon/fast-checker.ts`: Inbox + Telegram polling loop
- `src/pty/agent-pty.ts`: Claude Code PTY spawning with env var injection
- `src/bus/message.ts`: Inbox send/check/ack with HMAC signing
- `src/utils/paths.ts`: Canonical `BusPaths` resolver — single source of truth for all directory locations
- `dashboard/src/lib/db.ts`: SQLite schema and singleton
- `dashboard/src/lib/sync.ts`: Sync engine that populates SQLite from disk files

**Testing:**
- `tests/sprint*.test.ts`: Integration tests (Vitest)
- `tests/unit/`: Unit tests by module
- `tests/e2e/lifecycle.test.ts`: E2E daemon lifecycle test
- `tests/playwright/`: Browser-based Playwright tests

## Naming Conventions

**Files:**
- `kebab-case.ts` for all source files
- `hook-{event-type}.ts` for hook scripts in `src/hooks/`
- `sprint{N}-{topic}.test.ts` for integration test suites
- `[name]/route.ts` for Next.js API route handlers (App Router convention)

**Directories:**
- `kebab-case` for all directories
- `(group)/` for Next.js route groups (parentheses)
- `[param]/` for Next.js dynamic segments

**Classes:**
- PascalCase: `AgentManager`, `AgentProcess`, `IPCServer`, `FastChecker`, `TelegramAPI`

**Types:**
- PascalCase interfaces and type aliases: `AgentConfig`, `BusPaths`, `CtxEnv`, `InboxMessage`
- Enums as `const` maps: `PRIORITY_MAP`, `VALID_PRIORITIES`

## Where to Add New Code

**New bus operation (agent capability):**
- Implementation: `src/bus/{operation}.ts`
- CLI subcommand: add to `src/cli/bus.ts` busCommand
- Export from: `src/bus/index.ts`
- Tests: `tests/unit/bus/` or new `tests/sprint{N}-{topic}.test.ts`

**New CLI command:**
- Implementation: `src/cli/{command}.ts` exporting a `Command` instance
- Register in: `src/cli/index.ts` via `program.addCommand(...)`

**New daemon IPC command:**
- Add to `IPCCommandType` union in `src/types/index.ts`
- Handle in: `IPCServer.handleRequest()` switch in `src/daemon/ipc-server.ts`
- Call from: `AgentManager` method (add method there first)

**New Claude Code hook:**
- Implementation: `src/hooks/hook-{name}.ts`
- Register in: `templates/{type}/.claude/settings.json` hooks config

**New dashboard page:**
- Route file: `dashboard/src/app/(dashboard)/{page}/page.tsx`
- Add data fetching in `dashboard/src/lib/data/{domain}.ts`
- Add API route if needed: `dashboard/src/app/api/{endpoint}/route.ts`

**New agent template:**
- Directory: `templates/{name}/` with all required markdown files
- Add to `VALID_TEMPLATES` in `dashboard/src/app/api/agents/route.ts`

**New community skill:**
- Directory: `community/skills/{skill-name}/` with skill markdown and shell scripts

## Special Directories

**`dist/`:**
- Purpose: Compiled TypeScript output
- Generated: Yes (by `tsup`)
- Committed: No (gitignored)

**`dashboard/.next/`:**
- Purpose: Next.js build output and cache
- Generated: Yes
- Committed: No (gitignored)

**`~/.cortextos/{instanceId}/`:**
- Purpose: Runtime state directory — all agent state, inbox, logs, SQLite cache
- Generated: Yes (by daemon + CLI on first run)
- Committed: No (user-local)
- Layout: `inbox/`, `inflight/`, `processed/`, `logs/`, `state/`, `orgs/`, `config/`, `dashboard/`

**`~/.claude/projects/`:**
- Purpose: Claude Code conversation history (managed entirely by Claude Code)
- Generated: Yes (by Claude Code)
- Committed: No

**`orgs/`:**
- Purpose: Actual agent definitions for this install (gitignored in typical installs)
- Generated: By `cortextos init` + `cortextos add-agent`
- Committed: Conditionally (users may choose to commit their orgs directory)
